# Stay22 tester on staging

The original gated Kyoto-only modal was a connectivity rehearsal. The approved next iteration replaces it with an inline search immediately below the current stop heading on Stay. Keep the canonical staging host and verified tester-account gates, leave the public pilot settings off, and do not change main.

Use the selected overnight stop’s coordinates, exact upcoming dates, specified adults and supported trip currency. Never substitute a sample stop or guessed dates. The tester can change the adult count without changing the trip. Use the Morrovia controls outside the frame and the supported map accent inside it. Show a map and results at wide widths; at narrow widths start with the map and provide a Map/List switch. The gated surface replaces the legacy finder only for this tester.

Once the verified tester has opted into both Analytics and Affiliate Tracking, the actual stop search loads inline automatically. Before that, do not load any partner resource. Remove the frame on withdrawal or invalid/missing search details. Refresh it with the new exact search if dates, stop or group changes. Do not pass trip/account identifiers, names, emails or a referring page.

Property links open an external booking site, not an in-app selection. No documented property-selection callback is used. An actual booking can be explicitly recorded by the traveller with its name; this writes only to the current overnight visit, using the normal trip-save flow and never replacing an existing stay. Never treat browsing as booking.
