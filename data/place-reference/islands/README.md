# Reviewed island geography subset

This separate versioned subset supports Santorini, Crete, Tenerife, Gran Canaria and physical Bohol island. Canary Islands is a **partly covered archipelago**, with Tenerife and Gran Canaria as its two covered members. Other islands, mainland Spain, offshore water and sibling-island towns cannot qualify through these records. This is not global coverage.

Captured-body digests validate every record. Where original response bytes were retained, their original digests and lossless body relationship are checked too; parsed-only historical captures make no original-byte claim. Official Canary membership retains its actual checked public HTML response and digest.

The compressed records retain independently acquired public source bodies, source URLs/queries, exact identities, check dates and source publication timestamps. The reviewed manifest is pinned in the server build; runtime manifest changes cannot certify themselves. Its checksums protect those captures and 278 derived GeoNames town-to-island relationships. The normalizer keeps the original settlement ID/provider/point. It does not replace a town with an island centroid. When the GeoNames reference snapshot changes, regenerate and review the derived bindings against that snapshot; the physical source captures and geometry need no recapture if their bytes are unchanged.

Santorini and Crete use physical OSM multipolygons. Tenerife and Gran Canaria use complete independently tagged physical coastlines and the unique closed land component containing the exact named island identity point. Their political/maritime identity relations do **not** supply the land geometry. Polygon holes, boundary exclusion, closure and joint topology checks across all captured components remain strict. No path is patched, approximated, simplified or inferred from proximity. Canary member relationships retain exact Photon country/state and a checked official membership citation, independently of physical town containment.

## Explicit offline refresh

1. Acquire fresh bounded public source responses independently of traveller requests. Preserve exact URL/query, original response SHA256 where available, source timestamp and actual acquisition/check date. A failed request cannot replace a capture. Do not advance a check date merely by reusing old source data.
2. Prepare a `version:1` source pack containing `records` and `groups`. Each island record contains `id`, `name`, `country`, `geometryKind` (`island-relation`, `coastline` or `geofabrik-relation-v1`), and `identity`/`geometry` evidence (`url`, `checkedAt`, `body`, optional `query` and `originalResponseSHA256`). Identity evidence is a bounded Photon response; geometry evidence is a bounded Overpass response or the explicitly derived, versioned Geofabrik subgraph described below. A group additionally names its covered member IDs, exact archipelago identity evidence, HTTPS official membership citation, checked date and `coverage:'partial'`. Official membership citations require human source review; a URL alone does not certify point containment.
3. Run `node --experimental-strip-types scripts/build-island-geography.ts SOURCE_PACK.json NEW_CANDIDATE_DIRECTORY`. The command performs no network requests and refuses to overwrite any existing output. It checks exact source identities, countries, strict complete geometry, named group membership and installed reference facts before atomically publishing a candidate directory.
4. Review source/data/coverage differences and test the candidate. Only after review replace this accepted version through a normal Git change/deployment. Do not update running trips, schedule an external job or acquire provider credentials as part of refresh.

Suggested review cadence: monthly and on a reported geographic error. Old checked dates remain visible provenance; an outage or elapsed date does not switch a covered record back to user-blocking live requests. Unknown individual islands retain the existing bounded live source path. Covered-but-corrupt data fails closed with the existing recoverable API error, rather than pretending to be uncovered.

Separate bounds:2MiB compressed/deployed,8MiB inflated,128MiB incremental cold-load RSS,2seconds first covered-parent load,500ms warm lookup. Audit this subset and total deployed geographic data separately; do not change the existing32MiB reference-manifest budget to accommodate it. The server loads covered records lazily, validates source integrity and topology once and memoizes immutable geometry.

## Bohol: explicit Geofabrik PBF subgraph

Bohol is the physical island OSM relation `3625899`, version 95, not the province relation `1550487`. Its identity retains the original Photon response and original-byte digest, checked 2026-10-20. Its physical source is the dated public [Philippines archive](https://download.geofabrik.de/asia/philippines-261019.osm.pbf), captured 2026-10-20, 610,792,462 bytes. SHA256: `a3d44832f456485dcda5e0c649c3eecabe364a0baa47af2d8f70eaa122066c35`; [published MD5](https://download.geofabrik.de/asia/philippines-261019.osm.pbf.md5): `cc857ee6ad7062cb88fae2bf25fbef7f`. The captured PBF header gives source base `2026-10-19T20:21:11Z`, replication sequence 4944. This is OSM data distributed by Geofabrik under ODbL 1.0, not government boundary certification.

`geofabrik-relation-v1` uses geometry evidence with `body.version=1`, `body.format=geofabrik-osm-relation-subgraph-v1`, `archive`, `relation`, `ways` and `nodes`. `archive` retains exact immutable URL/bytes/SHA256/MD5, published checksum URL and body, base timestamp/replication sequence, ODbL licence/link and extraction method/script SHA256. The outer evidence has its actual check date and canonical JSON body SHA256. This derived graph is **not an original HTTP JSON response**: original-response fields are forbidden for this format. The 611 MB archive is not a runtime dependency or bundled payload.

The reviewed offline extraction uses PyOsmium 4.3.2 with exact native ID filters: read relation `3625899`, collect every referenced way, then every node referenced by those ways. Copy all IDs, versions, tags, roles, node order and exact coordinates; normalize timestamps to UTC `Z` and member type `w` to `way`. The record retains the complete 274 ways, 8,725 unique nodes and 8,999 point occurrences. No simplify/clip/repair operation is allowed. The original archive checksum and complete reference resolution were verified at capture; source review must reproduce that verification before accepting a different archive. Runtime validates/pins the reviewed subgraph and archive provenance through the build manifest, rather than fetching the archive or asserting that a stored digest independently proves remote data.

The adapter rejects duplicate, missing and unrelated records, invalid object versions or future timestamps, malformed archive/identity/licence/checksum evidence and oversized graphs. It reconstructs the existing physical geometry input from unchanged referenced coordinates; all existing member/point/topology/deadline, holes and exact-boundary rules remain. GeoNames bindings are regenerated from actual point containment. Tagbilaran City's unchanged reference tuple lies inside; Palawan homonyms, Siquijor and Panglao are outside. This geographic proof does not establish travel suitability.

To refresh, retain the old source files/group, independently capture and verify the dated archive, perform that complete ID extraction, form the versioned graph, compute `bodySHA256` over `JSON.stringify(body)`, and feed the complete source pack into the existing offline generator. Review all data/behaviour differences and both dataset budgets before replacing a version. Bare `Bohol` now participates in the existing exact-local candidate path and still needs an explicitly chosen real base. Other phrase qualification and ranking algorithms are unchanged.

The complete derived graph is distributed in `bohol.json.gz` under the same ODbL terms as the other island source records. Before publishing a product containing the derivative, verify that the required attribution/licence/data availability is provided to its recipients; backend asset tracing alone does not establish public availability. This local candidate does not authorize publication.
